# M2 需求文档

> 里程碑：M2 数据中台
> 目标读者：产品经理 / 项目负责人
> 状态：✅ 已交付（2026-06-02）

---

## 一、背景与目标

M1 完成了登录鉴权和用户管理。M2 的目标是建立**数据中台**，把运营工作所需的三类核心数据（红人、产品、爆款脚本）统一沉淀到数据库，为后续 M3 AI 工具模块提供数据基础。

**核心价值**：
- 管理员集中管理红人档案和产品信息，运营人员随时查阅
- 爆款脚本库积累素材，供 AI 仿写工具直接调用
- 告别旧架构的本地文件散落，数据统一入库可查

---

## 二、用户角色与使用场景

| 角色 | 主要场景 |
|---|---|
| 管理员 | 新建/编辑红人档案、上传人格文档、管理产品信息、维护爆款库 |
| 运营 | 查看红人档案和内容规划、查看产品信息，为使用 AI 工具做准备 |

## 三、功能需求

### 3.1 红人管理（管理员端）

**红人列表页** `/admin/kols`
- 展示所有红人，支持按状态（在档/已归档）、负责人筛选，支持按姓名/抖音ID搜索
- 支持分页
- 每行操作：进入详情、归档

**新建红人** `/admin/kols/new`
- 填写基础信息：姓名（必填）、抖音ID、抖音主页链接、人设标签、负责人
- 可直接粘贴人格档案 Markdown 和内容规划 Markdown，作为第一版档案保存

**红人详情** `/admin/kols/[id]`，5 个功能 Tab：

| Tab | 功能 |
|---|---|
| 人格档案 | 展示当前版本 Markdown，支持上传 .md/.docx 覆盖更新（版本号自动递增） |
| 内容规划 | 同上 |
| 关联产品 | 展示该红人关联的产品列表，可新增关联 |
| 素材库 | 展示该红人的参考素材列表（M2 仅查看，M3 补充上传） |
| 历史版本 | 展示所有档案版本记录（版本号/时间/创建人），可预览历史内容 |

---

### 3.2 产品管理（管理员端）

**产品列表页** `/admin/products`
- 展示所有产品，支持按状态筛选、关键词搜索
- 每行操作：进入详情、归档

**新建产品** `/admin/products/new`
- 填写：产品名（必填）、品类、价格、目标受众、使用场景

**产品详情** `/admin/products/[id]`，三个内容块：

| 区块 | 功能 |
|---|---|
| 机制卖点卡 | 展示背书/机制/种草三段内容，支持上传 .docx 文档自动解析填入 |
| 爆款文案 | 展示与该产品关联的爆款脚本 |
| 对标文案库 | 展示与该产品关联的对标素材 |

---

### 3.3 爆款库（管理员端）

**爆款库** `/admin/viral-scripts`
- 4 个类型 Tab：人设爆款 / 千川爆款 / 直播间爆款 / TikTok 爆款
- 每个 Tab 支持按关联红人、关联产品筛选
- 支持新建、编辑、删除爆款记录
- 字段：标题、来源链接、点赞数、发布时间、逐字稿、结构化 Markdown、关联红人、关联产品

---

### 3.4 运营端

**首页** `/`
- 红人卡片墙：展示所有在档红人（头像/姓名/抖音ID/标签），点击进入只读详情
- 产品卡片墙：展示所有在售产品（名称/品类/价格），点击进入只读详情
- 顶部全局搜索：支持搜索红人名/抖音ID/产品名，实时下拉展示结果

**红人只读详情** `/kols/[id]`
- 仅展示人格档案、内容规划两个 Tab，无任何编辑操作

**产品只读详情** `/products/[id]`
- 展示卖点卡、爆款文案、对标文案，无任何编辑操作

## 四、数据说明

M2 涉及以下数据库表：

| 表名 | 说明 |
|---|---|
| `kols` | 红人主表 |
| `kol_profiles` | 红人档案版本表（支持多版本，isCurrent 标记当前版） |
| `materials` | 红人素材表 |
| `products` | 产品主表 |
| `product_selling_points` | 产品卖点卡版本表 |
| `viral_scripts` | 爆款脚本库 |
| `benchmark_scripts` | 对标文案库 |
| `kol_product_relations` | 红人与产品的多对多关联 |
