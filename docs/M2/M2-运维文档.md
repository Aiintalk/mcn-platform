## 1. 升级 Node.js v18 → v20

> M1 遗留问题，M2 开始前完成。

```bash
# 使用 nvm（推荐）
nvm install 20
nvm use 20
nvm alias default 20

# 验证
node -v   # 应显示 v20.x.x
npm -v
```

如果服务器没有 nvm：

```bash
# 方式二：直接安装

sudo yum install -y nodejs     # CentOS/Alibaba Linux
# 或
sudo apt-get install -y nodejs # Ubuntu
```

升级后验证项目能正常构建：

```bash
cd /app/mcn-platform
pnpm install
pnpm build
```

## 2. PM2 cluster 配置

### 2.1 创建 ecosystem.config.js

在项目根目录 `/app/mcn-platform/` 新建：

```javascript
// ecosystem.config.js
module.exports = {
  apps: [{
    name: 'mcn-web',
    script: 'node_modules/.bin/next',
    args: 'start',
    cwd: './apps/web',
    instances: 4,              // 用满 4 核
    exec_mode: 'cluster',
    max_memory_restart: '1G',  // 单 worker 超 1G 自动重启
    env_production: {
      NODE_ENV: 'production',
      PORT: 3000
    },
    // 日志配置
    out_file: '/var/log/mcn-platform/out.log',
    error_file: '/var/log/mcn-platform/error.log',
    log_date_format: 'YYYY-MM-DD HH:mm:ss',
    merge_logs: true
  }]
}
```

### 2.2 创建日志目录

```bash
mkdir -p /var/log/mcn-platform
```

### 2.3 启动 / 管理命令

```bash
# 首次启动
pm2 start ecosystem.config.js --env production

# 代码更新后热重载（不中断服务）
pm2 reload ecosystem.config.js --env production

# 查看状态（应看到 4 个 online 的 mcn-web 进程）
pm2 list

# 查看实时日志
pm2 logs mcn-web

# 查看内存/CPU 监控
pm2 monit

# 设置开机自启
pm2 startup
pm2 save
```

### 2.4 验证 cluster 模式


## 3. Nginx 配置

### 3.1 完整配置文件

```nginx
# /etc/nginx/conf.d/mcn-platform.conf

upstream mcn_backend {
    server 127.0.0.1:3000;
    keepalive 32;
}

server {
    listen 80;
    server_name <你的域名>;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name <你的域名>;

    # SSL 证书（阿里云证书路径）
    ssl_certificate     /etc/nginx/ssl/mcn-platform.pem;
    ssl_certificate_key /etc/nginx/ssl/mcn-platform.key;
    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_ciphers         HIGH:!aNULL:!MD5;

    # 静态资源缓存
    location /_next/static/ {
        proxy_pass http://mcn_backend;
        proxy_cache_valid 200 365d;
        add_header Cache-Control "public, max-age=31536000, immutable";
    }

    # 主入口
    location / {
        proxy_pass http://mcn_backend;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;

        # 流式 AI 输出必须关闭缓冲
        proxy_buffering off;
        proxy_read_timeout 120s;   # AI 流式请求最长 2 分钟
        proxy_connect_timeout 10s;
    }

    # 上传文件大小限制（文档上传）
    client_max_body_size 20M;

    # 日志
    access_log /var/log/nginx/mcn-platform-access.log;
    error_log  /var/log/nginx/mcn-platform-error.log;
}
```

### 3.2 应用配置

```bash
# 测试配置语法
nginx -t

# 重载（不中断服务）
nginx -s reload
```

## 4. 数据库 M2 迁移

### 4.1 执行迁移

M2 后端完成 schema 变更后，按如下流程上线：

```bash
cd /app/mcn-platform

# 1. 拉最新代码
git pull origin main

# 2. 安装依赖
pnpm install

# 3. 执行数据库迁移（生产用 deploy，不用 dev）
pnpm --filter web db:deploy

# 4. 构建
pnpm build

# 5. 热重载（零停机）
pm2 reload ecosystem.config.js --env production
```

### 4.2 迁移验证

```bash
# 连接数据库检查新表是否存在
psql -U postgres -d mcn_platform -c "\dt"

# 预期新增表（M2 已有，确认存在）：
# kols / kol_profiles / products / product_selling_points
# viral_scripts / benchmark_scripts / materials / kol_product_relations
```

### 4.3 迁移回滚预案

如果迁移后出现问题：

```bash
# 回滚到上一个迁移版本
pnpm --filter web exec prisma migrate resolve --rolled-back <migration_name>

# 回滚代码
git checkout <上一个稳定 tag>
pnpm build
pm2 reload ecosystem.config.js --env production
```

## 5. 数据库连接池配置

### 5.1 更新 .env.production

```bash
# 在 DATABASE_URL 末尾加连接池参数
DATABASE_URL="postgresql://user:pass@localhost:5432/mcn_platform?connection_limit=5&pool_timeout=10"
```

### 5.2 验证 Postgres 连接数

```bash
# 运行中查看当前连接数（不超过 20 为正常）
psql -U postgres -d mcn_platform -c "SELECT count(*) FROM pg_stat_activity WHERE datname='mcn_platform';"
```

### 5.3 调整 Postgres max_connections（如需）

```bash
# 查看当前设置
psql -U postgres -c "SHOW max_connections;"

# 默认 100，4 worker × 5 连接 = 20，远低于上限，无需修改
# 如果将来扩容 worker，按 worker数 × 5 + 10 的公式调整
```

## 6. 备份策略

### 6.1 数据库自动备份脚本

```bash
# /etc/cron.d/mcn-platform-backup
# 每天凌晨 3 点备份，保留最近 7 天

0 3 * * * postgres pg_dump mcn_platform | gzip > /backup/mcn_platform_$(date +\%Y\%m\%d).sql.gz

# 删除 7 天前的备份
0 4 * * * find /backup -name "mcn_platform_*.sql.gz" -mtime +7 -delete
```

```bash
# 创建备份目录
mkdir -p /backup
chown postgres:postgres /backup

# 手动测试备份
pg_dump mcn_platform | gzip > /backup/mcn_platform_test.sql.gz
ls -lh /backup/
```

### 6.2 OSS 文件（无需备份）

阿里云 OSS 标准存储自带多副本冗余，不需要额外备份。

## 7. 监控与告警

### 7.1 PM2 监控

```bash
# 实时查看所有进程状态
pm2 monit

# 查看最近 100 行日志
pm2 logs mcn-web --lines 100

# 查看错误日志
tail -f /var/log/mcn-platform/error.log
```

### 7.2 需要关注的异常信号

| 现象 | 可能原因 | 处理方式 |
|---|---|---|
| 某个 worker 频繁重启 | 内存泄漏或未捕获异常 | 查 error.log，找堆栈 |
| 响应变慢 | DB 连接池耗尽 | 查 pg_stat_activity |
| 503 错误 | 所有 worker 同时重启 | pm2 list 查状态，手动重启 |
| 上传失败 | OSS 密钥过期或网络问题 | 检查 OSS 控制台 |
