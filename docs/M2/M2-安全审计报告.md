## 二、问题汇总与修复状态

### CRITICAL（3项，全部已修复）

| # | 问题 | 位置 | 修复方案 | 状态 |
|---|---|---|---|---|
| C-01 | `NEXTAUTH_SECRET` 使用可预测占位符，无启动校验 | `.env.local` | 生产环境用 `openssl rand -base64 32` 生成随机值，由运维替换 | ✅ 运维已操作 |
| C-02 | 所有 `[id]` 路由直接 `BigInt(params.id)`，非数字参数触发 500，可被 DoS | 全部动态路由 | `api-helpers.ts` 新增 `parseBigIntId()`，加正则 + PG bigint 上界校验，全部路由统一替换 | ✅ 已修复 |
| C-03 | 版本号在事务外读取，并发上传可导致版本冲突 | `upload-profile`、`profile`、`upload-selling-points` | `findFirst`（读 maxVersion）移入 `prisma.$transaction` 内部，与 `updateMany` + `create` 原子执行 | ✅ 已修复 |

### HIGH（6项，全部已修复）

| # | 问题 | 位置 | 修复方案 | 状态 |
|---|---|---|---|---|
| H-01 | 登录和改密接口无速率限制，可暴力破解 | `api/auth`、`api/users/me/change-password` | 新建 `lib/rate-limit.ts`，固定窗口 60s/10次，按 IP + bucket 隔离；优先取 nginx 注入的 `x-real-ip` | ✅ 已修复 |
| H-02 | `POST /api/kols` 和 `PATCH /api/kols/[id]` 使用 `requireAuth` 而非 `requireAdmin` | `kols/route.ts`、`kols/[id]/route.ts` | 改为 `requireAdmin` | ✅ 已修复 |
| H-03 | URL 字段未校验协议，可存入 `javascript:` 等恶意值 | 多个路由 | `api-helpers.ts` 新增 `isValidHttpUrl()`，用 `new URL()` 解析，只允许 `http:`/`https:` | ✅ 已修复 |
| H-04 | `publishAt` 用 `new Date(用户输入)` 未校验，无效日期静默写入 | `viral-scripts` 两个路由 | `api-helpers.ts` 新增 `parseSafeDate()`，`isNaN(d.getTime())` 兜底，无效值返回 400 | ✅ 已修复 |
| H-05 | PATCH body 字段仅判断 `!== undefined`，非字符串类型绕过类型检查 | `kols/[id]`、`viral-scripts/[id]` | 每个字符串字段先加 `typeof !== 'string'` 守卫，再做格式校验 | ✅ 已修复 |
| H-06 | 全站无安全 Headers（CSP、X-Frame-Options 等） | 无 | `next.config.ts` 新增 `headers()` 函数，注入 CSP（生产不含 `unsafe-eval`）、`X-Frame-Options: DENY`、`X-Content-Type-Options: nosniff`、`Referrer-Policy` | ✅ 已修复 |

## 三、新增工具函数（api-helpers.ts）

修复过程中在 `src/lib/api-helpers.ts` 新增以下工具函数，供所有路由复用：

```typescript
// BigInt ID 安全解析：正则校验 + PG bigint 上界

// HTTP/HTTPS URL 格式校验
isValidHttpUrl(value: unknown): value is string

```

## 五、运维端待执行事项

> 以下两项为服务器端操作，需运维人员 SSH 登录后执行。

**1. 替换 NEXTAUTH_SECRET**
```bash
# 生成随机 secret
openssl rand -base64 32

# 写入生产环境配置
vi /opt/dev/mcn-platform/apps/web/.env.production
# 将 NEXTAUTH_SECRET 替换为上面生成的值

# 同步到 .env
cp /opt/dev/mcn-platform/apps/web/.env.production \
   /opt/dev/mcn-platform/apps/web/.env

# 重启应用
cd /opt/dev/mcn-platform && pm2 reload mcn-web
```

**2. 创建专用数据库用户**
```sql
-- 以 postgres 超级用户登录
psql -U postgres -d mcn_platform

-- 创建专用用户（替换 <强密码> 为随机生成的密码）
CREATE USER mcn_app WITH PASSWORD '<强密码>';
GRANT CONNECT ON DATABASE mcn_platform TO mcn_app;
GRANT ALL ON SCHEMA public TO mcn_app;
GRANT ALL ON ALL TABLES IN SCHEMA public TO mcn_app;
GRANT ALL ON ALL SEQUENCES IN SCHEMA public TO mcn_app;
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT ALL ON TABLES TO mcn_app;
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT ALL ON SEQUENCES TO mcn_app;
```

然后更新 `.env.production` 中的 `DATABASE_URL`：
```
DATABASE_URL="postgresql://mcn_app:<强密码>@localhost:5432/mcn_platform?connection_limit=5&pool_timeout=10"
```
