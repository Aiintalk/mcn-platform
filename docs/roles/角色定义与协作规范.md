## 一、角色定义

### 🎨 前端 Agent

**职责**
- 实现所有页面 UI 与交互逻辑
- 管理前端状态与组件
- Mock 数据阶段先行开发，联调阶段对接真实接口

**工作目录（只操作这些路径）**
```
mcn-platform/apps/web/src/app/          ← 页面路由
mcn-platform/apps/web/src/components/   ← 共享组件
mcn-platform/apps/web/src/lib/mock/     ← Mock 数据
mcn-platform/apps/web/src/lib/api/      ← API 调用函数（联调时新建）
mcn-platform/apps/web/src/types/        ← 前端类型定义
```

**禁止操作**
- ❌ 不改 `src/app/api/` 下的任何文件（后端领域）
- ❌ 不改 `prisma/`（后端领域）
- ❌ 不改服务器配置文件（运维领域）
- ❌ 不改 `.env.local`（环境变量由运维/后端定）

**对外依赖**
- 依赖后端提供的 `API_CONTRACT.md` 了解接口格式
- Mock 数据结构必须与 API 契约字段保持一致

---

### ⚙️ 后端 Agent

**职责**
- 实现所有 API Route Handler
- 维护 Prisma schema 与数据库迁移
- 编写输入验证（Zod）与业务逻辑

**工作目录（只操作这些路径）**
```
mcn-platform/apps/web/src/app/api/      ← API 路由
mcn-platform/apps/web/src/lib/auth.ts   ← 鉴权配置
mcn-platform/apps/web/src/lib/prisma.ts ← Prisma 客户端
mcn-platform/apps/web/src/lib/api-helpers.ts ← 响应工具函数
mcn-platform/apps/web/prisma/           ← Schema 与迁移
mcn-platform/packages/lib-*/            ← 共享库（ai/asr/oss/tikhub）
```

**禁止操作**
- ❌ 不改 `src/app/(admin)/`、`src/app/(operator)/`（前端页面，前端领域）
- ❌ 不改 `src/components/`（前端领域）
- ❌ 不改服务器配置（运维领域）

**对外输出**
- 每次新增/修改接口后，**必须更新 `API_CONTRACT.md`**
- 数据库 schema 变更后生成迁移文件并提交

---

### 🖥️ 运维 Agent

**职责**
- 管理服务器环境与部署流程
- 维护 Nginx / PM2 / PostgreSQL 配置
- 执行数据库迁移上线
- 监控与备份

**工作目录（只操作这些路径）**
```
mcn-platform/ecosystem.config.js        ← PM2 配置
mcn-platform/apps/web/.env.example      ← 环境变量模板（不含真实值）
/etc/nginx/conf.d/mcn-platform.conf     ← Nginx 配置（服务器上）
/app/mcn-platform/                      ← 生产部署目录（服务器上）
```

**禁止操作**
- ❌ 不改业务代码（`src/`，前端/后端领域）
- ❌ 不改 Prisma schema（后端领域）
- ❌ 不直接修改 `.env.local` 以外的环境变量文件（`.env.production` 只在服务器上操作）

**对外输出**
- 本地环境准备好后通知前端/后端可以 `pnpm install && pnpm dev`
- 服务器环境就绪后输出部署状态报告

## 二、开发顺序（Sprint 节奏）

### 阶段 0 · 环境准备（运维先行，约半天）

**只有运维 Agent 工作，前端/后端等待。**

```
运维 Agent 任务：
1. 本地：确认 Node.js v20+、pnpm、PostgreSQL 15 均可用
2. 本地：确认 pnpm install 成功
3. 本地：执行 db:deploy + db:seed，确认数据库就绪
4. 本地：pnpm --filter web dev 启动成功，登录页可访问
5. 输出：「本地环境就绪」报告（✅/❌ 逐项列出）
```

✅ **阶段 0 完成后**，前端和后端同时启动。

---

### 阶段 1 · M2 并行开发（前端 + 后端同时跑，运维待命）

**前端和后端并行，互不阻塞。**

```
前端 Agent（并行）：               后端 Agent（并行）：
━━━━━━━━━━━━━━━━━━━              ━━━━━━━━━━━━━━━━━━━
按 M2-前端开发文档.md              按 M2-后端开发文档.md
用 Mock 数据开发所有页面            实现三套 API
不依赖后端接口完成                  每完成一套更新 API_CONTRACT.md
```

**运维 Agent 在阶段 1 期间做：**
```
1. 服务器 Node.js 升级 v18 → v20
2. 配置 ecosystem.config.js（PM2 cluster 4 worker）
3. 配置 Nginx（含 proxy_buffering off）
4. 配置数据库连接池（DATABASE_URL 加参数）
5. 配置备份 cron
```

---

### 阶段 2 · 联调（前端等后端接口，串行）

**后端 API 全部完成后，前端切换为真实接口。**

```
后端 Agent：
- 确认所有接口通过本地测试
- 更新最终版 API_CONTRACT.md
- 通知前端「接口就绪」

前端 Agent：
- 新建 src/lib/api/ 目录
- 逐模块将 mock 替换为真实接口调用
- 联调验收：页面功能完整可用
```

---

### 阶段 3 · 上线（运维主导，前端/后端配合）

```
运维 Agent：
- 拉最新代码到服务器
- pnpm install && pnpm build
- pnpm --filter web db:deploy（生产迁移）
- pm2 reload ecosystem.config.js --env production
- 验收：访问生产域名，登录可用

前端/后端 Agent：
- 配合处理上线发现的问题
```

## 三、协作接口（Agent 间的唯一交互点）

Agent 之间**不直接通信**，通过以下文件交换信息：

| 文件 | 写入方 | 读取方 | 用途 |
|---|---|---|---|
| `mcn-platform/API_CONTRACT.md` | 后端 | 前端 | 接口格式约定 |
| `mcn-platform/apps/web/prisma/schema.prisma` | 后端 | 运维 | 迁移依据 |
| `mcn-platform/apps/web/.env.example` | 后端/运维 | 前端/后端 | 环境变量清单 |
| `docs/M2/M2-*.md` | 产品经理 | 各 Agent | 任务说明 |
