# 发布流程文档

> 适用对象：开发人员、运维
> 前提：服务器已按《服务器部署文档》完成初始化

---

## 一、整体流程概览

```
本地开发（feat/* 分支）
        │
        ▼
   合并到 main 分支
        │
        ▼
   推送到远程仓库（GitHub / Gitee）
        │
        ▼
   SSH 登录服务器，执行 deploy.sh
        │
        ▼
   git pull → pnpm install → db:deploy → pnpm build → pm2 reload
```

---

## 二、第一步：配置远程仓库（只做一次）

### 2.1 在 GitHub / Gitee 创建私有仓库

1. 登录 GitHub 或 Gitee，新建私有仓库，名称如 `mcn-platform`
2. 不要勾选「初始化 README」（本地已有代码）

### 2.2 本地关联远程仓库

```bash
cd D:\2026年工作\AI相关\AI工具箱新架构方案\aiintalk\mcn-platform

# 添加远程（以 GitHub 为例，替换为实际地址）
git remote add origin git@github.com:你的账号/mcn-platform.git

# 推送所有分支
git push -u origin main
git push -u origin dev
```

### 2.3 服务器配置 SSH Key（用于 git pull）

在服务器上生成 SSH Key，添加到 GitHub / Gitee 的「Deploy Keys」（只读权限即可）：

```bash
# 在服务器上执行
ssh-keygen -t ed25519 -C "mcn-platform-server" -f ~/.ssh/mcn_deploy
cat ~/.ssh/mcn_deploy.pub
# 复制输出的公钥内容，粘贴到 GitHub → 仓库 Settings → Deploy Keys
```

配置 SSH 使用该 Key：

```bash
cat >> ~/.ssh/config <<EOF
Host github.com
  HostName github.com
  User git
  IdentityFile ~/.ssh/mcn_deploy
EOF
```

### 2.4 服务器首次克隆项目

```bash
cd /opt
git clone git@github.com:你的账号/mcn-platform.git mcn-platform
cd mcn-platform

# 配置环境变量（参考《服务器部署文档》第四章）
nano apps/web/.env.production

# 安装依赖、迁移、构建、启动
pnpm install --frozen-lockfile
pnpm db:deploy
pnpm db:seed      # 仅首次执行
pnpm build
pm2 start ecosystem.config.js --env production
pm2 save
```

## 三、日常发布流程（每次上线新版本）

### 3.1 本地：合并代码并推送

```bash
# 在本地开发机执行
cd D:\...\mcn-platform

# 1. 确保功能分支已测试通过
git checkout feat/m2-xxx

# 2. 合并到 main
git checkout main
git merge feat/m2-xxx --no-ff -m "feat: M2 xxx 功能上线"

# 3. 推送到远程
git push origin main
```

### 3.2 服务器：执行部署脚本

SSH 登录服务器后，运行一键部署脚本：

```bash
ssh 用户名@服务器IP
cd /opt/mcn-platform
bash scripts/deploy.sh
```

脚本会自动完成：拉取代码 → 安装依赖 → 数据库迁移 → 构建 → 热重载，**全程无需停机**。

---

## 四、deploy.sh 脚本说明

脚本位置：`scripts/deploy.sh`（见下一章）

| 步骤 | 命令 | 说明 |
|---|---|---|
| 1 | `git pull origin main` | 拉取最新代码 |
| 2 | `pnpm install --frozen-lockfile` | 仅安装依赖，锁定版本 |
| 3 | `pnpm db:deploy` | 执行未执行的 Prisma 迁移 |
| 4 | `pnpm build` | Next.js 生产构建 |
| 5 | `pm2 reload mcn-web` | 集群滚动重启，零停机 |

任意步骤失败，脚本立即中止并打印错误，**不会执行后续步骤**。

## 五、紧急回滚

如果新版本上线后发现问题，快速回滚到上一个版本：

```bash
cd /opt/mcn-platform

# 查看最近的 commit
git log --oneline -10

# 回滚到指定 commit（替换 <hash> 为目标版本的 commit hash）
git checkout <hash>

# 重新构建并重载
pnpm build
pm2 reload mcn-web
```

> **注意**：如果新版本包含数据库迁移，回滚前需手动还原数据库，建议先备份：
> ```bash
> sudo -u postgres pg_dump mcn_platform | gzip > /backup/mcn_platform_before_rollback.sql.gz
> ```

## 六、分支规范

| 分支 | 用途 | 合并目标 |
|---|---|---|
| `main` | 生产环境，只接受合并，不直接提交 | — |
| `dev` | 集成测试分支 | `main` |
| `feat/*` | 功能开发分支 | `dev` 或 `main` |

**推荐流程**：`feat/*` → 本地测试 → 合并 `main` → 推送 → 服务器 `deploy.sh`

## 七、常见问题

### Q：push 后服务器怎么知道要更新？

目前是**手动触发**：push 后 SSH 登录服务器执行 `deploy.sh`。  
如需自动化，可在 GitHub Actions 中配置 CD，push 到 main 时自动 SSH 触发脚本（M3 阶段可考虑）。

### Q：数据库迁移失败怎么办？

```bash
# 查看迁移状态
cd /opt/mcn-platform && npx prisma migrate status --schema apps/web/prisma/schema.prisma

# 手动修复后重试
pnpm db:deploy
```

### Q：构建失败如何排查？

```bash
# 查看详细错误
pnpm build 2>&1 | tail -50

# 常见原因：环境变量未配置、依赖版本不一致
cat apps/web/.env.production
```

### Q：pm2 reload 后日志有报错？

```bash
pm2 logs mcn-web --lines 100
```
