# 数据库初始化文档

> 适用阶段：服务器首次部署
> 工具：PostgreSQL 15 + Prisma 5

---

## 一、原理说明

项目使用 **Prisma Migrate** 管理数据库结构，不需要手动写 SQL 建表。

| 文件 | 作用 |
|---|---|
| `apps/web/prisma/schema.prisma` | 数据模型定义（单一数据源） |
| `apps/web/prisma/migrations/20260601105757_init/migration.sql` | Prisma 自动生成的建表 SQL（已包含所有表、索引、外键） |
| `apps/web/prisma/seed.ts` | 初始数据脚本（初始账号 + 示例数据） |

执行顺序：**建库 → 配环境变量 → `db:deploy`（建表）→ `db:seed`（初始数据）**

---

## 二、步骤

### Step 1：在服务器上创建数据库

SSH 登录服务器，执行：

```bash
sudo -u postgres psql <<EOF
CREATE USER mcn_user WITH PASSWORD '替换为强密码';
CREATE DATABASE mcn_platform OWNER mcn_user;
GRANT ALL PRIVILEGES ON DATABASE mcn_platform TO mcn_user;
EOF
```

验证是否创建成功：

```bash
sudo -u postgres psql -c "\l" | grep mcn_platform
# 应输出：mcn_platform | mcn_user | UTF8 | ...
```

---

### Step 2：配置环境变量

在服务器项目目录下创建 `.env.production`：

```bash
nano /opt/mcn-platform/apps/web/.env.production
```

写入（**替换密码和密钥**）：

```env
DATABASE_URL="postgresql://mcn_user:替换为强密码@localhost:5432/mcn_platform?schema=public&connection_limit=10&pool_timeout=20"
NEXTAUTH_SECRET="替换为64位随机字符串"
NEXTAUTH_URL="https://你的域名"
NODE_ENV="production"
```

生成 `NEXTAUTH_SECRET`：
```bash
openssl rand -base64 48
```

---

### Step 3：执行数据库迁移（建表）

```bash
cd /opt/mcn-platform
pnpm db:deploy
```

这条命令等同于：
```bash
prisma migrate deploy --schema apps/web/prisma/schema.prisma
```

执行成功后，PostgreSQL 中会自动创建以下内容：

**枚举类型（4 个）**

| 枚举名 | 值 |
|---|---|
| `Role` | `admin`, `operator` |
| `user_status` | `active`, `disabled` |
| `kol_status` | `active`, `archived` |
| `product_status` | `active`, `archived` |
| `viral_script_type` | `persona`, `qianchuan`, `livestream`, `tiktok` |

**数据表（11 张）**

| 表名 | 说明 |
|---|---|
| `users` | 用户账号 |
| `kols` | 红人主表 |
| `kol_profiles` | 红人档案（支持多版本，isCurrent 标记当前版） |
| `materials` | 红人素材库 |
| `products` | 产品主表 |
| `product_selling_points` | 产品卖点卡（带版本） |
| `viral_scripts` | 爆款脚本库 |
| `benchmark_scripts` | 对标文案库 |
| `kol_product_relations` | 红人↔产品多对多关联 |
| `outputs` | AI 工具产出记录 |
| `tool_usage_logs` | 工具调用流水 |

**索引（4 个）**
- `users_username_key`：用户名唯一索引
- `kols_douyin_id_key`：抖音 ID 唯一索引
- `idx_outputs_tool_user`、`idx_outputs_kol`、`idx_outputs_product`：产出记录查询索引
- `idx_tool_usage_logs_time`：调用流水时间索引

验证建表成功：

```bash
sudo -u postgres psql -d mcn_platform -c "\dt"
# 应列出 11 张表
```

---

### Step 4：写入初始数据（仅首次执行）

```bash
cd /opt/mcn-platform
pnpm db:seed
```

Seed 会创建以下初始数据（使用 upsert，**重复执行安全**）：

**初始账号**

| 账号 | 密码 | 角色 | 说明 |
|---|---|---|---|
| `zhangchong` | `Admin@123456` | 管理员 | 首次登录强制改密 |
| `operator01` | `Operator@123` | 运营 | 测试账号 |
| `operator02` | `Operator@456` | 运营 | 测试账号 |

**示例数据**
- 3 个示例红人（示例红人 A/B/C）
- 示例红人 A 附带初始档案（版本 1）
- 1 个示例产品（示例产品 X，护肤品类）

> 生产环境上线后，示例数据可在管理后台直接归档或删除。

## 三、验证数据库是否正常

```bash
# 登录数据库查看表记录数
sudo -u postgres psql -d mcn_platform <<EOF
SELECT COUNT(*) AS 用户数 FROM users;
SELECT COUNT(*) AS 红人数 FROM kols;
SELECT COUNT(*) AS 产品数 FROM products;
EOF
```

预期输出：
```
 用户数
--------
      3

 红人数
--------
      3

 产品数
--------
      1
```

## 四、后续迁移说明（每次数据库结构变更）

每次后端修改了 `schema.prisma` 并新增了迁移文件后，服务器只需执行：

```bash
cd /opt/mcn-platform
pnpm db:deploy
```

Prisma 会自动识别哪些迁移已执行、哪些未执行，**只执行增量部分**，不会重复执行。

> `db:deploy` 只应用迁移，不会生成新迁移，适合生产环境使用。  
> 生成新迁移是 `db:migrate`（开发环境命令，**不要在服务器上执行**）。
